- 测试代码统一放在根目录下的 `tests` 文件夹内。
- 每个接口都必须有接口测试：走真实路由与鉴权，覆盖状态码、响应结构、错误码；正常、失败、边界三类都要有。
- 单元测试只覆盖重要代码：核心业务逻辑、鉴权/权限判定、输入校验、金额/状态流转、事务与并发逻辑；纯 CRUD、getter/setter、薄封装不强制。新增或修改上述五类代码时必须同时提交单元测试。
- 失败路径至少覆盖：参数非法、未认证/无权限、资源不存在、依赖不可达。
- 修 bug 先补能复现的失败用例，再改到通过。
- 断言必须检查具体值（返回码、字段、条数），禁止只断言"不抛异常"。
- 测试数据独立准备和清理，不依赖执行顺序、真实网络、生产数据或真实密钥。
- 一条命令跑全部测试，失败即阻断合并；新 clone 能复现。
- 每次运行测试必须生成报告，归档到 `reports/` 子文件夹；目录不存在则创建，已存在则覆盖该次运行的文件。
- 该子文件夹内按固定文件名生成：
  - `security-precheck.md`：接口清单、身份与数据、每条用例的三段式记录与当前判定
  - `risk-authz.md`：权限类用例展开，含可原样再跑的复测命令
  - `risk-concurrency.md` / `risk-transaction.md`：并发与事务类用例的复现记录
  - `security-baseline.md`：密钥扫描与依赖审计的命令与输出原文
  - `review-01.md`：交叉评审记录，四件事写全（手段 / 查了什么 / 判据 / 结果）
  - `test-report.md`：本次运行汇总——用例总数、通过/失败/跳过数、失败用例名称与错误摘要、运行时间、提交号、是否留红
- 每条用例按三段式写：前置条件 / 操作 / 可观测结果与当前实际；当前实际必须是可再跑出同一个数的具体值，不写"通过""没问题"。
- 报告目录可由运行命令的 `--report-dir` 覆盖；未指定时默认 `reports/`。
